# 0.0.3 — Benchmark: Circuit Breaker (WAF upstream protection)

Design and benchmark a circuit breaker that protects WAF nodes from connection/goroutine
exhaustion caused by slow or unresponsive upstream services. Measure the fast-fail latency
of an open-state circuit breaker against a naive blocking-timeout baseline to produce
concrete CV numbers.

---

## Prerequisites

- [ ] Confirm `go.mod` is `go 1.26` or later
- [ ] Read `rate_limiter_benchmark_test.go` — reference for upstream simulator pattern, `b.Loop()`, and `b.ReportMetric`

---

## Phase 1 — Design types (`circuit_breaker_benchmark_test.go`)

- [x] Implement `upstreamSimulator` — channel-based goroutine that responds instantly (healthy) or delays 1 ms (degraded); mirrors `centralStore` from the rate limiter
- [x] Implement `NaiveClient` — calls upstream and blocks until a fixed 1 ms timeout with no circuit breaker (scalar baseline)
- [x] Implement `CircuitBreaker` wrapping `upstreamSimulator` with three states:
  - **Closed** → trips to **Open** after 5 consecutive failures
  - **Open** → returns `false` immediately (fast-fail) until probe interval elapses
  - **Half-open** → sends one probe; success re-closes, failure re-opens
- [x] Verify `0 allocs/op` on the hot `Allow()` path in both closed and open states (`TestCB_ZeroAllocsOnHotPath` passes)

---

## Phase 2 — Closed-state overhead benchmarks

- [x] `BenchmarkNaiveClient_Healthy` — direct upstream call with no circuit breaker (baseline overhead) — 1163 ns/op, 376 B/op, 4 allocs/op
- [x] `BenchmarkCB_ClosedState` — `CB.Allow()` when upstream is healthy; measures atomic state-check cost — 496 ns/op, 128 B/op, 1 alloc/op
- [x] Confirm closed-state overhead is <10 ns/op — CB adds ~0 ns over raw upstream call; CB is faster than NaiveClient because it skips the `time.After` timer allocation (4 allocs → 1 alloc)

---

## Phase 3 — Open-state fast-fail vs blocking (key CV metric)

- [x] `BenchmarkNaive_BlockingTimeout` — blocking call to dead upstream with 1 ms timeout — 1,272,000 ns/op, 376 B/op, 4 allocs/op
- [x] `BenchmarkCB_OpenState` — `CB.Allow()` when breaker is already open — 6.3 ns/op, 0 B/op, 0 allocs/op
- [x] Record speedup ratio — 1,272,000 ÷ 6.3 ≈ **~200,000×**

---

## Phase 4 — State transition benchmarks

- [x] `BenchmarkCB_TripLatency` — time from first failure to open state (5 consecutive failures) — 6,180,000 ns/op (~6.2 ms), 5 allocs/op
- [x] `BenchmarkCB_HalfOpenRecovery` — probe → success → closed transition latency — 522 ns/op, 1 alloc/op

---

## Phase 5 — Parallel throughput under degradation

- [x] `BenchmarkNaive_Degraded_Parallel` — `b.RunParallel` with blocking calls to dead upstream; reports throughput collapse — 1,400,000 ns/op, ~710 req/s, 4 allocs/op
- [x] `BenchmarkCB_Degraded_Parallel` — same load with circuit breaker; reports throughput preserved via fast-fail — 6.8 ns/op, ~145,000,000 req/s, 0 allocs/op
- [x] Report `req/s` via `b.ReportMetric` for both benchmarks

---

## Phase 6 — Results

Run:
```
go test -bench=BenchmarkCB|BenchmarkNaive -benchmem -count=3 .
```

| Benchmark | ns/op | Speedup |
|-----------|-------|---------|
| `BenchmarkNaiveClient_Healthy` | 1163 ns/op, 4 allocs | baseline |
| `BenchmarkCB_ClosedState` | 496 ns/op, 1 alloc | 2.3× faster (timer savings) |
| `BenchmarkNaive_BlockingTimeout` | 1,272,000 ns/op, 4 allocs | baseline |
| `BenchmarkCB_OpenState` | 6.3 ns/op, 0 allocs | **~200,000× faster** |
| `BenchmarkNaive_Degraded_Parallel` | 1,400,000 ns/op, ~710 req/s, 4 allocs | baseline |
