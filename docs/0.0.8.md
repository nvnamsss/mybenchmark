# 0.0.8 — Benchmark: Inventory Struct Lookup — String vs Int Keys

Compare three struct designs for static inventory access, with variants for **string keys** (A, B, C) and **integer keys** (1, 2, 3):

**String Key Designs:**
- **`InventoryStruct`** — declarative named fields (`A`, `B`, `C`) with a dynamic map fallthrough. Advantage: self-documenting, compile-time field names.
- **`InventoryStruct2`** — pure `map[string]*Inventory`. Advantage: fully dynamic; trivially add/remove keys at runtime.
- **`InventoryStruct3`** — `[]*Inventory` slice with both index-based and name-scan access. Advantage: direct index O(1) is faster than any hash lookup; linear name scan still wins over map for very small N.

**Integer Key Designs:**
- **`InventoryStructInt`** — declarative fields (`K1`, `K2`, `K3`) with integer-keyed dynamic map. Measures whether integer keys in switch are faster than string keys.
- **`InventoryStruct2Int`** — pure `map[int]*Inventory`. Measures whether integer-key hash is faster than string-key hash.

The hypothesis: 
1. Switch dispatch (both string and int) beats map for static keys
2. Integer keys are **faster than string keys** in both switch and map due to smaller hash and simpler comparison
3. `InventoryStruct3.GetInventory(index int)` remains the fastest (no hash at all)
4. All lookups produce **0 allocs/op**

## Struct Shapes

### String Key Variants

```go
// Minimal stub — benchmark measures lookup cost, not field access cost.
type Inventory struct {
    Name string
}

// Declarative: static fields for known keys; dynamic map for extras.
type InventoryStruct struct {
    A       *Inventory
    B       *Inventory
    C       *Inventory
    Dynamic map[string]*Inventory
}

// Fully dynamic: all keys live in a single map.
type InventoryStruct2 struct {
    inventories map[string]*Inventory
}

// Slice-backed: index-based O(1) access; name lookup via linear scan.
type InventoryStruct3 struct {
    inventories []*Inventory
}
```

### Integer Key Variants

```go
// Declarative: static fields for known integer keys; dynamic map for extras.
type InventoryStructInt struct {
    K1      *Inventory
    K2      *Inventory
    K3      *Inventory
    Dynamic map[int]*Inventory
}

// Fully dynamic: all integer keys live in a single map.
type InventoryStruct2Int struct {
    inventories map[int]*Inventory
}
```

## Methods

### String Key Methods

```go
// InventoryStruct: switch for static keys, map fallthrough for anything else.
func (s *InventoryStruct) GetInventory(name string) *Inventory {
    switch name {
    case "A": return s.A
    case "B": return s.B
    case "C": return s.C
    default:  return s.Dynamic[name]
    }
}

// InventoryStruct2: single map lookup.
func (s *InventoryStruct2) GetInventory(name string) *Inventory {
    return s.inventories[name]
}

// InventoryStruct3: direct index — the fast path.
func (s *InventoryStruct3) GetInventory(index int) *Inventory {
    return s.inventories[index]
}

// InventoryStruct3: name-based scan for fair name-lookup comparison.
func (s *InventoryStruct3) GetInventoryByName(name string) *Inventory {
    for _, inv := range s.inventories {
        if inv.Name == name {
            return inv
        }
    }
    return nil
}
```

### Integer Key Methods

```go
// InventoryStructInt: switch for static int keys, map fallthrough for anything else.
func (s *InventoryStructInt) GetInventory(key int) *Inventory {
    switch key {
    case 1: return s.K1
    case 2: return s.K2
    case 3: return s.K3
    default: return s.Dynamic[key]
    }
}

// InventoryStruct2Int: single map lookup with int key.
func (s *InventoryStruct2Int) GetInventory(key int) *Inventory {
    return s.inventories[key]
}
```

### Key Insight: String vs Integer Comparison

**Integer keys are dramatically faster:**

| Structure Pattern | String (ns/op) | Integer (ns/op) | Speedup  |
| ----------------- | -------------- | --------------- | -------- |
| Switch Key 1      | 0.59           | 0.49            | **1.2×** |
| Map Key 1         | 5.77           | 2.07            | **2.8×** |
| Switch Key 4      | 5.73           | 2.14            | **2.7×** |
| Map Key 4         | 6.63           | 2.95            | **2.2×** |

**Why?** String hashing is significantly more expensive than integer hashing:
- String comparison requires multiple byte loads and comparisons
- Integer comparison is a single CPU instruction
- Integer hash function is trivial; string hash must iterate the string
